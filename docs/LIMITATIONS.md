# Limitations

1. **Data is simulated.** All infrastructure data (assets, services, vulnerabilities, advisories) is synthetically generated by `data/generate_dataset.py` with seed 42. No real infrastructure is scanned or connected.

2. **Attestations are only as truthful as signers.** A malicious org signer could submit false risk bands or dependency claims. Bilateral confirmation (BC-ATT-D-01) and the challenge mechanism (BC-SEC-08) mitigate but do not eliminate this risk.

3. **LLM suggestions are never authoritative.** The LLM parses advisory text, writes narratives, and proposes plan orderings. All numeric risk scores come from the deterministic model. All plans are validated by the CriticAgent's independent re-implementation.

4. **Local chain is not decentralised.** The Hardhat network runs locally for development and testing. A production deployment would use a permissioned consortium network.

5. **Dev keys are insecure by design.** Private keys in `data/orgs/*/private_keys.dev.json` are generated for local testing only and are git-ignored.

6. **ML model trained on synthetic data.** The risk model (RISK-01) trains on `historical_incidents.csv`, which is synthetically generated. AUC ≥ 0.80 is achievable on the synthetic split but does not imply real-world performance.

7. **Dashboard on-chain verification is partial.** DASH-10 requires direct ethers.js reads for Audit Verification and Attestations views; other views may read via the backend API.

8. **No real-world remediation.** The ExecutorAgent mutates only simulated state (AG-ACT-01). No actual patches, credential rotations, or network changes are performed.
