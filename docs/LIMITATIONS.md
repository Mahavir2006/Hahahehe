# Limitations

1. **Data is simulated.** All infrastructure data (assets, services, vulnerabilities, advisories) is synthetically generated by `data/generate_dataset.py` with seed 42. No real infrastructure is scanned or connected.

2. **Attestations are only as truthful as signers.** A malicious org signer could submit false risk bands or dependency claims. Bilateral confirmation (BC-ATT-D-01) and the challenge mechanism (BC-SEC-08) mitigate but do not eliminate this risk.

3. **LLM suggestions are never authoritative.** The LLM parses advisory text, writes narratives, and proposes plan orderings. All numeric risk scores come from the deterministic model. All plans are validated by the CriticAgent's independent re-implementation.

4. **Local chain is not decentralised.** The Hardhat network runs locally for development and testing. A production deployment would use a permissioned consortium network.

5. **Dev keys are insecure by design.** Private keys in `data/orgs/*/private_keys.dev.json` are generated for local testing only and are git-ignored.

6. **ML model trained on synthetic labels.** M1 trains on `data/ml/gen_a.csv`: simulated assets with real, time-matched CVE context (CISA CSAF, KEV) and labels from a synthetic process with hidden factors (`data/label_process.py`). On held-out generator A it reaches ROC-AUC 0.7447, below the spec target of 0.80, and ties logistic regression (0.7455); on generator B it reaches 0.6678. These numbers measure agreement with the simulation, not real-world skill. Details in `docs/ML_REPORT.md`.

7a. **Hand-set constants are assumptions.** The cascade weights (`EDGE_WEIGHT`, `SERVICE_WEIGHT`, `BAND_P`, `STRENGTH_W`), the impact weights (0.45 / 0.20 / 0.15 / 0.20), the monitoring (x0.85) and isolation (x0.3) multipliers, the 2.0-point band hysteresis are chosen, not learned. The band thresholds (8.91 / 15.03 / 38.74) are percentiles of M1's output on simulated data, so bands are relative ranks and must be re-derived after retraining. A +-20% sensitivity check keeps top-10 rankings largely stable (Kendall tau 0.76-1.0, see `docs/ML_REPORT.md`).

7. **Dashboard on-chain verification is partial.** DASH-10 requires direct ethers.js reads for Audit Verification and Attestations views; other views may read via the backend API.

8. **On-chain confidentiality has residual metadata.** Values are hidden (SEC-PRIV), but the org-level dependency graph, timing and counts of attestations are visible to chain readers, and every consortium member can decrypt the shared bands/edges. See "What is still visible on-chain" in `docs/THREAT_MODEL.md`. Encryption keys are derived from the dev key files, which is not acceptable outside development.

9. **No real-world remediation.** The ExecutorAgent mutates only simulated state (AG-ACT-01). No actual patches, credential rotations, or network changes are performed.

## PS-03 additions (feature/ps03-completion)

10. **Labels are synthetic.** The v1 model's label is a formula of its own features, so its committed AUC (0.898) is optimistic; results describe simulated data only.
11. **Real data context is vendor-level.** Seeded CVEs (CISA CSAF OT snapshot) are matched to demo assets by vendor: 56 of 75 assets by vendor, 1 by model, 18 by sector fallback (measured). They describe plausible exposure, not confirmed exposure.
12. **EPSS is not time-matched.** FIRST EPSS scores are as of 2026-10-30 and used as a static CVE property. Never use them for a back-test.
13. **Detections are rules, not a trained detector.** Six deterministic rules over simulated telemetry. Their precision/recall (`backend/risk/artifacts/rules_metrics.json`) is circular, because the rules and the simulator were written together. R2 (unexpected remote access) has many false positives (precision 0.065).
14. **Cascade and what-if constants are assumptions.** EDGE_WEIGHT, SERVICE_WEIGHT, BAND_P, STRENGTH_W, impact weights and what-if multipliers are hand-set; the "why" payload labels them. Their sensitivity was not measured (WP10 not done).
15. **Trend is statistical.** Holt/EWMA over the reassessment log, back-tested only on synthetic histories against a weak naive baseline.
16. **The dashboard is a local demo.** It talks to a local Hardhat chain and a local API; containment is simulated and never reaches equipment.
17. **v1 cannot score a vulnerability without CVSS.** The existing intake fills a missing CVSS with 5.0; the PS-03 path never does, and seeded CVEs always carry a score.
