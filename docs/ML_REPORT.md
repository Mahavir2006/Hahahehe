# ML report (CascadeShield, PS-03)

Every number in the tables below is generated by `python evaluation/report_tables.py` from
`backend/risk/artifacts/metrics.json` and `data/ml/MANIFEST.json`, which `make evaluate` and the scripts in
`evaluation/` produce. All results are **on simulated data**: assets, telemetry and compromise labels are synthetic.
Nothing here shows that a model detects real attackers or predicts real incidents.

## 1. Row definition

One row = one asset in one 90-day observation window. Every feature is computed as of the window start t from
information available at or before t; telemetry features use the 30 days before t. The label is 1 if a simulated
compromise occurs in (t, t+90 days]. A test (`test_no_feature_uses_information_after_the_window_start`) and the
dataset build's leakage audit enforce the time cut-off.

## 2. Data: real versus simulated

| Part | Source | Real or simulated |
|---|---|---|
| CVE IDs, CVSS scores, advisory release dates, sector | CISA CSAF OT advisories snapshot (`data/real/vuln_snapshot.jsonl`) | **real**, time-matched to t |
| Known-exploited flag | CISA KEV (`data/real/kev.jsonl`, CC0), using dateAdded <= t | **real**, time-matched |
| Exploit probability | proxy `estimate_epss(cvss, kev_at_t)` | **proxy**: the real EPSS file is dated 2026-10-30 and not time-matched, so it is not used for training (`epss_source = proxy`) |
| Assets, zones, exposure, credentials, ports, patch history, firmware state | `data/ml_population.py` | simulated, with correlated draws |
| Network/OT telemetry and injected episodes | `data/telemetry.py` | simulated |
| Compromise labels | `data/label_process.py` (generators A and B, hidden factors, 6-7% label noise) | **synthetic**; real asset-level compromise labels do not exist publicly |
| Demo organisations (power, water, hospital, 25 assets each) | `data/orgs/` | simulated; used for inference and dashboards only, never for training |

Public ICS datasets (CIC Modbus 2023, SWaT, WADI) were not used; see "Not done".

## 3. Models and where they are used

| ID | What | Learned? | Where it runs |
|---|---|---|---|
| M1 | Compromise-likelihood classifier: HistGradientBoosting with monotonic constraints (asset type as an ordinal code), sigmoid-calibrated, SHAP on the base model | yes, supervised on synthetic labels | Risk Agent, through `backend/risk/inference.py` only |
| B1 / B2 / B3 | CVSS-only ranking / KEV flag / L2 logistic regression | B3 only | offline evaluation only |
| D | 6 detection rules over telemetry, plus one exposure rule | no (deterministic thresholds) | telemetry step before the Risk Agent; aggregated counts feed M1 |
| M4 | Holt linear trend and band-crossing estimate on stored risk snapshots | statistical, not ML | `backend/risk/trend.py`, reads the Risk Agent's snapshot history |
| M3 | Leakage adversary (random forest) against what is public on-chain | yes | offline evaluation only |
| M2 | Statistical anomaly signal | not built | see "Not done" |

What stays deterministic: impact (`impact_of`), final risk `risk = 100 x likelihood x (0.3 + 0.7 x impact)` in
integer basis points, the cascade engine, the planner's what-if wiring, the critic, the approval gate and the chain.

## 4. Key findings, in plain words

1. **Two bugs found by rigorous testing were fixed, and M1 retrained** (`docs/ML_DECISIONS.md` section 4): SHAP
   explanations did not add up (error up to 0.74 log-odds, now below 1e-14), and `num_dependents` meant direct
   dependents in training but transitive dependents in live scoring (PSI 3.57). All numbers below are after the fix.
2. **M1 ties logistic regression; it does not beat it.** On held-out generator A: ROC-AUC 0.7447 against B3's
   0.7455, PR-AUC 0.5437 against 0.5475. Generator A is close to additive in log-odds, which suits a linear model.
   M1 is kept because it guarantees that more exposure never lowers risk (0 monotonicity violations) and gives exact
   SHAP explanations. Pass criterion P3 is not met.
3. **M1 clearly beats the rule-of-thumb baselines.** PR-AUC 0.5437 against 0.249 (CVSS only) and 0.1824 (KEV only);
   precision of the top 5 of a 25-asset dashboard 0.4375 against 0.3016 and 0.1656.
4. **The spec target ROC-AUC 0.80 is not met** (0.7447 on held-out A). It was not used as a tuning goal; hidden
   factors and label noise cap any model. `make verify-spec` reports this measured value (it used to return a
   hard-coded 0.85).
5. **Accuracy is the wrong yardstick here, and the alert threshold is aggressive.** With 17-18% positives, always
   answering "safe" scores about 82% accuracy. At the operating threshold 0.12 (pre-registered rule: maximise F2,
   which favours catching compromises) M1 catches 76% of compromises at precision 0.25, so accuracy is 0.557. The
   threshold sweep shows the trade-off: at 0.3 accuracy is 0.846, precision 0.59, recall 0.41. Ranking does not use
   the threshold.
6. **Most of the AUC on A is "recovering the generator".** On generator B, ROC-AUC falls to 0.6678 (drop 0.0769).
7. **Calibration made things slightly worse.** The base model was already close to calibrated (ECE 0.0123); the
   pre-registered sigmoid step gives 0.0164. Pass criterion P5 is not met.
8. **Telemetry carries the most signal**: removing it costs 0.1879 PR-AUC. Caveat: precursors are generated from
   the labels by construction, so this mostly measures the simulation's assumption.
9. **KEV rows are scarce**: only 9 snapshot CVEs are in KEV, giving 54 KEV rows in generator A (observed compromise
   rate 0.685) and 6 in the test split, too few to evaluate that segment.
10. **No drift inside the simulation; real drift on the demo assets.** Held-out A, later windows and generator B all
    have prediction PSI below 0.02. The 75 demo assets differ from the training population (prediction PSI 0.3452):
    they are patched less recently (about 390 days), carry no CVE until an advisory arrives and have no
    supply-chain flags before the firmware check. That reflects the demo inventory, not a bug, but it means demo
    scores sit at the edge of what M1 was trained on.
11. **Band thresholds are derived from M1** by the rule fixed before computing them (50th / 80th / 95th percentile
    of risk on held-out A): 8.91 / 15.03 / 38.74 after the retrain. The headline advisory raises `power-asset-001`
    from 10.06 to 33.64 = high, which triggers the cross-org alert. Before any advisory, the 75 demo assets are
    54 low, 19 medium, 2 high, 0 critical. Bands are relative ranks, not absolute probabilities.
12. **The on-chain privacy layer holds for identities, not for timing.** M3 maps a hash to its named service at
    0.319 against 0.2592 chance, but infers "this service is currently high/critical" from attestation and alert
    timing at 0.8271 against a 0.6667 majority baseline. This rests on the adversary simulation's own assumption that
    busy services are hot; it supports the residual risk listed in `docs/THREAT_MODEL.md`.

## 6. Integration contract (implemented)

- `predict_likelihood(features) -> {likelihood_bp, model_version, top_factors, missing, data_source_tags}` in
  `backend/risk/inference.py` is the only path to M1. `top_factors` carry true SHAP values in log-odds of the
  uncalibrated base model; a test checks they sum to the base model's log-odds.
- Integer arithmetic: `risk_bp = round_half_up(likelihood_bp * (30_000_000 + 7_000 * impact_bp), 10^8)`; risk = risk_bp / 100.
- Stable `model_version` = sha256(schema + hyperparameters + training-data hash + seed + sklearn version)[:16];
  metrics are not hashed. The artifact sha256 is checked before loading; a missing or mismatched artifact fails closed.
  joblib executes code on load, so only artifacts produced by `backend/risk/train_model.py` are trusted.
- Band hysteresis: an attested band changes only when the score clears a boundary by 2.0 points.
- `what_changed(before, after)` returns the top 3 SHAP-delta contributors with a sentence each; `model.why(asset)`
  returns source CVEs, key factors, likelihood next to impact next to risk, cascade assumptions, data freshness and
  a source tag per input.
- What-if changes real features (patch, firmware update, credentials, segmentation, port closure, isolation);
  monitoring (x0.85) and the residual isolation effect (x0.3) remain hand-set multipliers, documented as assumptions.
- Old "points" (risk x SHAP / total) are gone from SHAP fields; a share of risk is still shown as
  `share_of_risk_not_shap`.

## 7. Limits

- Labels are synthetic; any metric measures agreement with the simulation, not real-world skill.
- The EPSS feature is a proxy of CVSS and KEV.
- Only 9 KEV CVEs exist in the snapshot, so the known-exploited region is thinly trained.
- Band thresholds are percentiles of M1's own output on simulated data, so a band means a relative rank, not an absolute probability; they must be re-derived whenever M1 is retrained.
- Telemetry precursors are drawn from the labels, so telemetry importance is partly built in.
- Demo assets get benign-only simulated telemetry; some benign anomalies trip rules D1, D2 and D5 (see the D table).
- Rules D1, D2 and D5 have low precision (0.23 to 0.45) because benign off-calendar activity looks like the attack signal.

## 9. Reproduce

```bash
python data/build_ml_dataset.py
python -m backend.risk.train_model
python -m backend.risk.evaluate_model
python evaluation/m4_backtest.py
python evaluation/sensitivity.py
python evaluation/m3_adversary.py
python evaluation/report_tables.py
```

Or `make generate-data train-model evaluate`. Seeds are fixed (42), `n_jobs=1`, and two trainings give the same
model version, artifact hash and predictions.
